一个面向个人造价从业者的本地工程造价工作台。你可以导入自己的历史清单和常用定额，建立项目、编制报价、保存版本、收录案例，并用造价参考和 AI 辅助下一次判断。资料默认保存在浏览器 IndexedDB，也可切换为用户授权的本地文件夹 JSON 存储；AI Key 仅保存在本机 `localStorage`。

当前版本：`v6.2`，重点完善材料设备主数据、不可变价格历史、附件证据、资源组成、完整备份和并发安全。

## 快速开始

建议通过本地静态服务运行，避免浏览器拦截 ES Module 或演示数据加载：

```bash
python3 -m http.server 8000
```

然后打开 `http://localhost:8000/app/` 进入实际工作台。`http://localhost:8000/` 是产品介绍落地页，两者用途不同；不建议直接双击 HTML 文件。

## 功能模块

| 模块 | 作用 |
| --- | --- |
| 我的概览 | 继续最近工作，查看待补单价、待保存版本和个人资料完整度 |
| 我的定额库 | 维护常用定额、Excel 导入、分类/单位/价格状态筛选 |
| 我的材料库 / 我的设备库 | 维护材料设备主数据、不可变价格快照、报价附件和定额引用 |
| 我的项目 | 新建、编辑、收录案例，并直接进入项目清单 |
| 工程量清单 | 选择定额、填写工程量、批量调价、保存报价版本、报价审查和导出报价单 |
| 造价参考 | 基于已收录案例统计极值、分位数、中位数和均值 |
| AI 助手 | 本地指令 + 远端模型，用于查造价、推荐定额、检查缺单价 |
| 复盘笔记 | 将报价审查、版本调整和案例收录里的判断保存为可检索的个人经验 |
| 数据与备份 | AI 配置、本地数据文件夹、资料整理、JSON 备份恢复、演示数据加载和重置 |

## 数据导入与备份

定额 Excel 支持“清单名称 / 项目特征 / 单位 / 综合单价”等列。导入后会展示总行数、成功数、失败数、跳过数和缺单价数。综合单价为空或为 0 的条目会被标记为“缺单价”，生成报价时按 0 计。

工程量清单支持“报价版本管理”。当前清单是工作稿，点击“保存版本”会生成不可变快照；可在“版本管理”中查看历史版本、对比两个版本的增删改和总价变化，也可恢复某个版本覆盖当前清单。

保存报价版本、报价审查和案例收录都可以发起“报价复盘笔记”。系统会根据当前项目、清单、版本和质量报告生成追问，用户回答后生成笔记草稿，确认后才保存到个人复盘笔记。

### 材料与设备价格口径

材料、设备价格均保存为不可变快照；资源可手动指定首选价，否则系统按本地日历日期选择仍在有效期内的最新价格。三种价格口径含义如下：

- `ex_factory`（出厂价）：货物离开生产厂家时的价格，不含运至项目现场的运杂费用，也不含安装调试。
- `delivered`（到场价）：货物送达项目现场的价格，可包含约定的运费、运输损耗和采购保管费，不含现场安装调试。
- `installed_composite`（安装综合价）：按已填写的安装范围包含设备/材料、安装及可能的调试费用；用于定额或清单时应避免再重复计取人工、机械或安装费。

供应商报价建议关联原始依据。附件支持 PDF、JPG/JPEG、PNG、XLS 和 XLSX，单个文件必须大于 0 且不超过 20MB；系统同时校验扩展名、MIME 与文件签名。

## 数据自动沉淀

系统内置本地数据引擎，所有数据保存在当前本机存储模式中，不上传服务器。第一版采用审慎自动策略：

- 导入工程量清单 Excel 后，自动生成待检查记录和质量报告。
- 保存报价版本后，自动沉淀为不可变版本样本。
- 案例收录后，自动整理为可用案例并重算造价参考。
- 造价参考的“案例记录”可查看来源、质量、可用/待检查状态，并确认记录是否可用。
- 设置页的“数据整理”面板可查看采集、标准化、质量检查、保存和参考重建记录。
- 系统会为记录写入来源 ID、来源数据集、质量分和处理记录，便于后续追溯和排查。

缺单价、总价为 0、工程量为 0、未匹配定额的记录会标记为低可信或需复核。默认参考只使用可用案例，不直接使用临时工作稿。

## AI 复盘笔记

复盘采用“追问 → 草稿 → 确认保存 → 查阅复用”的轻闭环：

- 追问由 AI 优先生成；没有 API Key 时使用本地模板兜底。
- 复盘笔记包含结论、适用边界、风险提示、证据来源、可信度、有效期和复核状态。
- 复盘笔记以条目列表展示，支持关键词、项目类型、工艺类型、成本分类、状态和有效期筛选。
- AI 助手查询经验时优先检索已确认笔记，并记录引用次数。
- 复盘笔记不参与造价参考计算，只作为个人复盘和报价辅助资料。

默认 IndexedDB 模式下，业务表保存在各 store 中，附件元数据位于 `resource_attachments`，附件二进制按内部附件键独立保存。切换到用户授权的本地文件夹后，布局为：

```text
本地数据文件夹/
├─ manifest.json
├─ stores/*.json
├─ attachments/<resourceId>/<attachmentId>-<safeFileName>
└─ backups/*.json
```

设置页提供两类备份，导入文件上限均为 500MB：

- 兼容 JSON：用于旧版兼容和轻量留档，包含全部业务表与附件元数据，但不包含附件二进制；恢复后相应附件会标记为缺失。
- 完整 ZIP：包含业务数据、`manifest.json` 校验清单和附件原文件，是跨设备完整迁移附件的格式；压缩文件及安全解压后的总内容都受 500MB 限制。

ZIP 压缩/解压使用仓库内固定版本的 `assets/vendor/fflate/`，避免运行时访问公共 CDN，并确保备份格式行为可复现。所有 JSON/ZIP 备份都可能包含敏感业务数据，应存放在受控位置；API Key 不会随业务备份导出或被恢复覆盖。

## 测试

当前没有构建步骤，Vercel 以静态文件方式部署 `/app/`；前端依赖已放在 `assets/vendor/`，避免运行时依赖公共 CDN。运行轻量逻辑测试：

```bash
node tests/run.mjs
```

手动验证建议覆盖：`/app/` 启动与干净控制台、材料/设备导航和价格/附件、导入中心、定额七项费用与人材机组成、清单资源审查四组问题、设置页兼容 JSON/完整 ZIP 标签及恢复、仪表盘资源健康入口、数据刷新后持久化，以及 1440/1024/768/320px 下的布局与键盘焦点。任何恢复测试前都应先导出当前备份。
